=== VERDICT ===
MISLABEL CONFIRMED AND SCOPED: 52 of 60 resolved rows (86.7%) are stored
under a competition label that is not the competition they belong to.

Consequences that are NOT cosmetic:
  - Per-sport bucketing (anomaly baselines, the 2026-08-06 hygiene distributions) pools
    these rows into the wrong sport. The "FIFA World Cup" per-sport stats reported
    earlier this session are computed over a bucket that is partly other leagues.
  - soccerLeagueSlug() in drama-backfill.mjs derives an ESPN league slug FROM this
    stored label, so a wrong label sends historical fetches at the wrong competition.
  - analytics-engine.js maps both "FIFA World Cup" and "FIFA World Cup 2026" onto the
    WC26 config key, so non-WC rows inherit WC26 configuration.
  - Users see the wrong competition name on real fixtures.

The code fix is one expression at three sites: `gm.league` already holds the correct
label from the LEAGUES table, so the ternary that overrides it should simply be
dropped. NOT applied by this probe -- it lives in field-relay-nba, where a push to
src/** auto-deploys, and changing the label changes /archive/game's id construction
(id = `${sport}_${date}_...`). Rows already archived dedup on espn_event_id and are
safe, but a game SEEDED pre-game under the old id and finalized after the deploy
would write a second row rather than update the first. Human go/no-go, with a
deploy window chosen between slates rather than during one.
